Coursework

Lab Submissions

Five hands-on labs building up from basic UI to full local database persistence.

L1
Lab 1 — UI Fundamentals
Jetpack Compose · Basic layouts, Text, Button, Column, Row
Reflection Lab 1 introduced me to declarative UI with Jetpack Compose. I learned how composable functions replace the old XML layouts and how state management works differently compared to View-based Android. This foundation was essential for everything that followed.
L2
Lab 2 — User Interaction
Jetpack Compose · onClick, TextField, state hoisting
Reflection Lab 2 deepened my understanding of user interaction and state hoisting in Compose. Handling user input through TextField and reacting to onClick events made me realize how reactive programming patterns make UI logic much cleaner and more predictable.
L3
Lab 3 — Material Design
Material 3 · Theming, color schemes, typography, components
Reflection Applying Material Design 3 gave my app a professional, consistent look. I learned how to define a color scheme, apply typography scales, and use Material components like Cards, Buttons, and TopAppBars correctly — skills I carried directly into both projects.
L4
Lab 4 — Navigation
Navigation Compose · NavHost, NavController, multi-screen flow
Reflection Lab 4 was a turning point — connecting multiple screens through NavHost made the app feel like a real product. Understanding how to pass data between screens via ViewModel rather than navigation arguments was a key architectural insight I now apply everywhere.
L5
Lab 5 — Room Database
Room · Entity, DAO, Repository, Flow, local persistence
Reflection Room Database taught me how to persist data locally so it survives app restarts. Setting up the Entity, DAO, and Repository pattern was initially complex but made total sense once I saw data flowing through StateFlow into the UI automatically — no manual refresh needed.

Capstone Work

Projects

Two projects progressively building toward a fully connected, hardware-aware mobile app.

Project 1
JobHub — Multi-Screen Job Platform
Lab 4 foundation · Navigation · ViewModel · SDG 1
Problem Statement: Many Malaysians from the B40 community lack easy access to job opportunities. JobHub addresses SDG Goal 1 — No Poverty — by providing a mobile job platform that connects job seekers to employment listings and lets them apply directly from their phones.
Lessons Learned Project 1 solidified my ability to architect a multi-screen app with shared state via ViewModel. I learned how important it is to design navigation flows before writing code, and how a clear separation between UI and business logic makes the app easier to extend — which paid off greatly in Project 2.

Project 2
JobHub — Advanced: API, Sensors & Cloud
Room · Firebase Firestore · REST API · CameraX ML Kit · GPS
Problem Statement: Building on Project 1, JobHub now tackles the broader challenge of making job applications smarter and more accessible. The camera sensor reads IC cards to auto-fill forms, GPS finds nearby jobs, a live REST API provides Malaysia's national employment context, and Firebase keeps applications synced to the cloud.
Lessons Learned Project 2 taught me how to integrate multiple complex systems — Room, Firestore, Retrofit, CameraX, and FusedLocation — without them conflicting. I learned that coroutines and the Repository pattern are the glue that keeps everything clean. Most importantly, I learned that understanding your code deeply matters more than just making it work.

Learning Journey

Reflection

From my first Composable function to a fully connected cloud app.

When I started Lab 1, writing a simple Column with a Text and a Button felt like a new language. By the end of Project 2, I had built an 8-screen Android app that reads IC cards with a camera, detects GPS location, fetches live data from the internet, and syncs to Firebase Firestore in real time. The growth over these few months has been the steepest learning curve I have experienced in my studies.

The hardest challenge was not any single technology — it was learning to think in systems. Every new feature in Project 2 had to fit with Room, the ViewModel, and the navigation graph simultaneously. Learning to plan before coding, and to read error messages carefully rather than guessing, saved me more time than any shortcut.

Working on SDG Goal 1 — No Poverty — gave every lab and every late debugging session a real purpose. Building technology that could genuinely help B40 Malaysians find employment made the coursework feel meaningful, not just academic. I leave this course not just knowing how to build Android apps, but understanding why good software architecture matters for real people.

References

Resources & References

APIs, libraries, and tools used throughout this course.

REST Countries API
restcountries.com — free public API used in Project 2 to fetch Malaysia's national data (population, Gini index, currency) to support SDG 1 context on the Profile screen.
Firebase Firestore
firebase.google.com — cloud NoSQL database used in Project 2 to mirror job applications from the device to the cloud in real time.
Google ML Kit — Text Recognition & Barcode Scanning
developers.google.com/ml-kit — used in Project 2's IC Scanner screen to read Malaysian IC card numbers (OCR) and scan QR codes via CameraX image analysis.
Google Play Services — FusedLocationProviderClient
developers.google.com/location — GPS sensor integration used in Project 2's Nearby Jobs screen to detect the user's current city and filter job listings.
Retrofit 2 + Gson Converter
square.github.io/retrofit — HTTP client library used for REST Countries API calls, with Gson handling JSON deserialization into Kotlin data classes.
Accompanist Permissions
google.github.io/accompanist — Jetpack Compose library used to handle runtime permissions for Camera and Location in a declarative, composable way.
Android Developers Documentation
developer.android.com — primary reference for Room, Navigation Compose, CameraX, ViewModel, StateFlow, and all Jetpack libraries used throughout labs and projects.
